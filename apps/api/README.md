# Independently authored Astra API

Run from the repository root: `npm run db:migrate`, `npm run db:seed`, `npm run dev:api`. Local PostgreSQL connection settings come from ignored `.runtime/postgres.json`; deployments set `DATABASE_URL` for a NOBYPASSRLS application role and `DATABASE_ADMIN_URL` for migrations. Do not run the API as a PostgreSQL superuser. The runtime setup creates `astra_app` before migrations. The migration activates FORCE RLS on tenant tables and composite tenant foreign keys. Authentication derives the tenant from active server-side membership on every request.

`openapi.json` inventories new routes; runtime request validation in `src/app.ts`, `src/management.ts`, `src/portal-tools.ts` and the shared service schemas is authoritative. All47 services accept operational DEMO applications. The service schema endpoint defaults to the latest published version, supports a pinned `version`, and returns observed controls with `view=reference`. Creation selects the latest schema while edits/PDFs use the application-pinned immutable schema. The seed rejects hash drift in a published version. Historical v1 schemas and stored PDFs remain intact.

Application search supports `q`, `state`, `serviceNo`, `page`, `pageSize` (default/max100), returning `{items,total,page,pageSize}`. Detail includes `{application,payload,versions,events,citizen,certificate,renewal,serviceConfiguration}`. Office/notices lists are public, filtered before pagination and expose only active offices/published notices. Session cookies are HttpOnly/SameSite=Strict; mutations include the returned `X-CSRF-Token`. Set `PUBLIC_ORIGIN` to the exact UI origin. Production cookies require HTTPS; live official issuance remains unavailable (tenant `demo=true` database constraint).

Tenant admins manage office profiles, local accounts/memberships, service enablement/integer costs, published notices and service-specific DEMO approver grants. Owners can provision/suspend/reactivate offices, with no citizen or approval access. New offices begin with an expired subscription and zero credits until sandbox settlement/adjustment. Self-signup creates only a synthetic citizen. Password changes require the current password and expire other sessions. Admin-assisted recovery issues a one-use,15-minute token stored only as a hash; the administrator must manually convey it through a trusted channel. Recovery cannot target owners, admins, foreign/multi-office accounts, or inactive accounts, and expires all existing sessions. No email/SMS delivery is claimed.

Renewal creates a new normal-review application linked to an issued source for the same tenant, citizen and service. The database enforces one active successor; canceled/rejected renewals allow replacement. Trade previous-license numbers are server pinned. Source revocation blocks final issuance. Every successful renewed certificate consumes one new credit; retrying that issue does not consume another.

`npm run test:api` exercises the real PostgreSQL database, not a database emulator. Tests modify synthetic fixtures and append immutable events/ledger entries; they preserve balance=sum(ledger.delta). The test-only `X-Test-Failure: after-debit` hook runs solely when `NODE_ENV=test` and proves rollback before commit. No production route enables this hook.

PDF generation uses Chromium and installed Nirmala UI or Noto Sans Bengali for Bangla shaping. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` if Chromium is not in the Windows Playwright cache. Template4 renders service-specific approved fields and nested family/heir/correction rows with HTML escaping, private attachment indicators, language selection and QR status verification. Remote resource loading is blocked during rendering. PDF bytes, certificate, ledger debit and transactional outbox are persisted atomically after preparation. Concurrent retries may prepare redundant temporary in-memory PDFs; only one certificate and one charge commit. Each PDF is plainly `DEMO / NOT OFFICIAL`, uses synthetic applicants and contains no government marks.

Demo subscription/top-up orders have zero monetary value. The explicit synthetic settlement action signs an event using an ignored runtime HMAC key; webhook processing independently checks raw-body signature, amount, currency, order and event identity. It is not a commercial payment gateway. All statutory fee configuration remains `NOT_CONFIGURED` in separate database accounting.

Private upload validation checks decoded size and file signature; accepted files are `UNSCANNED`. Production malware scanning, content sanitization, lawful identity/OTP integration, official signatories, a worker for outbox delivery, commercial pricing/expiry policies and live payments remain release gates. No reference database, personal records, private code, tokens or government integrations are included.
