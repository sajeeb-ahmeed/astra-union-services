## Current common workflow

**Choose citizen → choose service → enter facts → review office options/fees → save draft → submit → review/correction → separate authorized approval → issue/download/verify.** A positive citizen-fee assessment stops at issuance until real collection is connected. This is Astra's independently implemented sequence, not a claim that the entire reference sequence was observed.

All unions share service schemas, application states, order UI, tenant access checks, history, document generation and the issuance ledger. Office configuration selects services, fees, delivery/urgency modes, jurisdiction and existing approval grants. SaaS plan/credits remain a separate commercial layer. Official signatory configuration and payment choices are future work, not current configuration features.

The selected 0.4 contract quotes before creation and stores one immutable order snapshot at creation/renewal. The backend recalculates prices, rejects stale policies and language disagreement, and preserves historical `LEGACY` applications. It does **not** implement quote IDs/expiry, post-creation order editing, arbitrary policy expressions, generic create-retry deduplication or payment callbacks. [Order workflow](ORDER_WORKFLOW.md) and [OpenAPI](../apps/api/openapi.json) are the current contracts; earlier illustrative wider proposals are not implemented endpoints.

## Remaining reference and product decisions

- Confirm complete common/specialist screen sequences, address choices and language-specific application/charge behavior using authorized synthetic cases.
- Supply approved office tariffs and determine actual collection timing/methods, receipt requirements, refunds, VAT/gateway charges and any coupon eligibility. The current code accepts explicit tariffs but does not determine their legal correctness.
- Specify official signatory appointment/configuration, service-specific document content/validity and approved-certificate amendment/reissue rules. Do not infer permission to overwrite issued history from a visible edit button.
- Verify renewal eligibility/carry-forward rules and service-specific geography dependencies. Current Astra lineage controls remain in force.

Safe follow-up evidence records labels, roles, options and outcomes separately. No captured citizen values, signatures, credentials, private screenshots or actual record references belong in public source/evidence.
