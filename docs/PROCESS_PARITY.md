## Current common workflow

**Choose citizen → choose service → enter facts → review office options/fees → save draft → submit → review/correction → separate authorized approval → positive-fee gateway checkout/verification → issue/download/verify.** The payment step is available only after approved merchant setup; current disabled checkout cannot collect money. Zero-fee and legacy paths retain their separate rules. This is Astra's independently designed sequence, not a claim that the reference sequence or its payment timing was fully observed.

All unions share service schemas, application states, order UI, tenant access checks, history, document generation and the issuance ledger. Office configuration selects services, fees, delivery/urgency modes, jurisdiction and approval grants. SaaS plan/credits remain separate. The first gateway adapter explicitly binds one merchant configuration to one tenant per deployment; other offices do not inherit that merchant. Multi-merchant onboarding, additional payment methods and official signatory configuration remain gaps.

The 0.4 contract quotes before creation and stores one immutable order snapshot at creation/renewal. The backend recalculates prices, rejects stale policies and language disagreement, and preserves historical `LEGACY` applications. It does **not** implement quote IDs/expiry, post-creation order editing, arbitrary policy expressions or generic application-create retry deduplication. The 0.5 gateway separately implements one durable payment intent per application, signed callback and query-based recovery; unresolved attempts cannot be automatically replaced. [Order workflow](ORDER_WORKFLOW.md), [gateway payments](GATEWAY_PAYMENTS.md) and [OpenAPI](../apps/api/openapi.json) are the current contracts.

## Remaining reference and product decisions

- Confirm complete common/specialist screen sequences, address choices and language-specific application/charge behavior using authorized synthetic cases.
- Supply approved office tariffs and determine actual collection timing/methods, receipt requirements, refunds, VAT/gateway charges and any coupon eligibility. The current code accepts explicit tariffs but does not determine their legal correctness.
- Specify official signatory appointment/configuration, service-specific document content/validity and approved-certificate amendment/reissue rules. Do not infer permission to overwrite issued history from a visible edit button.
- Verify renewal eligibility/carry-forward rules and service-specific geography dependencies. Current Astra lineage controls remain in force.

Safe follow-up evidence records labels, roles, options and outcomes separately. No captured citizen values, signatures, credentials, private screenshots or actual record references belong in public source/evidence.
